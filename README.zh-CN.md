# fact-check

[English](README.md) | [中文](README.zh-CN.md)

面向 AI agent 的递归声明核查协议。把它摆在任何一段话、一个结论、一句「我查过了」前面,它就不允许你的 agent 把自己没有真正追到可指认证据的东西标成已验证。

**定位**:反幻觉协议,不是「查资料的方法论」。唯一目标是让「没验证」在输出里无处藏身。

## 三个技能

| 技能 | 谁调用 | 干什么 |
|---|---|---|
| `fact-check` | 模型自动 + 人 | 方法本身:拆解 → 逐条递归追依据链 → 四态汇报。默认不落文件 |
| `fact-check-with-docs` | 人 / 编排器 | 第一次核查,产出 `核查-<主题>.md` |
| `fact-check-by-docs` | 人 / 编排器 | 读那份文档接着核查,只推进没打勾 / 有未处理 diff 的 |

后两个带 `disable-model-invocation: true`(同 `grill-me` / `grill-with-docs`):它们会写文件,所以只由人点名调用。两个壳里没有方法,方法都在 `fact-check`。

核查文档就是 Markdown:每条声明带状态,下面写依据(看了哪里 + 逐字原文),再一行 `[x] 谁 日期`;不认就写 diff(改前 / 改后)+ 理由。**打勾 = 我看过、我认,机器不能打勾**;复述别人的话也不算。没打勾的项,`grep -n "\[ \]" 核查-*.md` 一条命令全列出来 —— 不需要脚本。

## 它解决的问题

你问 agent「这是真的吗」,它会验证最容易的那两条声明,然后宣布整段话可信 —— 没验证过的部分悄悄继承了已验证部分的可信度。本协议针对的失败模式:

- 只核表面声明,漏掉隐含声明(这两个数字真能相除吗?相关是不是被说成因果?「大多数」量化了吗?)
- 把记忆、别的 agent 的结论、自己上一轮的判断当依据
- 用「应该是」「我印象中」「基本成立」代替核查
- 验证了某东西*存在*,就把整段话当成可信
- 出一份核查报告却不给分母,谁也看不出漏了什么

## 内核四条

1. **先拆解穷尽。** 把每一条可核查声明编号列出,含隐含声明 —— 并且在开始核查*之前*先交付这份清单。清单就是分母;没覆盖到的必须有地方可见地待着。
2. **递归追链。** 每条声明的每个依据,继续追问它自己的依据,直到终点。验证了 A 不覆盖 B。
3. **终点 = 「可指认证据终点」,不是「公理」。** 文件原文只证明文件这么写;命令输出只证明那条命令在那个环境产出了那个输出;网页只证明它此刻是那样记载的。这些是关于*材料*的证据,不是关于*世界*的证据 —— 权威统计是某个口径下的二次汇总,口径、样本、时间窗都可能错,所以永远拿不到最高级。
4. **逐条汇报 + 公示分母。** 每条声明一行,末尾给总数。「全部已验证」只有覆盖率真的是 100% 时才准说。

## SKILL.md 里有什么

- **声明分类**:排除(主观评价、偏好、用户自定前提)/ 列入但不可核查(未来预测、应然、价值判断)/ 列入且可核查
- **依据分级**:A(一手)/ B(来源如此记载)/ C(二手汇总、转述、翻译)—— 分级永远不能替代状态
- **四个状态**:`✓ 已验证` / `✗ 已证伪` / `? 未决` / `○ 未覆盖`,终端打不出符号时用 `OK / NO / ? / -`
- **未决的理由**:查无实据 / 来源矛盾 / 循环依据 / 超出能力 / 无权限 / 无数据
- **一个校准用例题** —— 规则说不清拆解粒度,只能靠例题

## 安装

### Claude Code

```bash
git clone https://github.com/NNZQniuniu/fact-check.git ~/.claude/skills/fact-check
```

### DSH,或任何扫 `~/.agents/skills` 的工具

```bash
git clone https://github.com/NNZQniuniu/fact-check.git ~/.agents/skills/fact-check
cp -r ~/.agents/skills/fact-check/skills/* ~/.agents/skills/
```

DSH 只扫一层(`<root>/<name>/SKILL.md`)。三个技能在同一个仓库里,所以克隆完要把两个壳复制到 skills 根目录的顶层 —— 上面第二行就是干这个的。

### 技能名必须是小写 kebab-case

这是改名之前唯一值得读的一条坑。DSH 在发现阶段就用 `/^[a-z0-9]+(?:-[a-z0-9]+)*$/` 校验 frontmatter 的 `name`,不合规的文件会被静默丢弃(`ignored: invalid skill name`),它根本进不了注册表,于是 skill 工具在去找这个技能之前就报 `invalid skill name`。**所以中文 `name:` 等于技能不存在**,目录叫什么无关紧要。

这就是为什么本仓库 frontmatter 写 `name: fact-check` 而正文是中文。**目录名不影响发现** —— 发现阶段读的是 frontmatter,文件夹叫 `事实核查` 完全可以。

## 用法

给它一段话,它先返回拆解,再逐条给状态:

```
输入:"某公司去年营收增长 20%,因为用户数翻倍。"

拆解:6 条声明
  ① 营收有增长(存在性)  ② 增幅 20%(数值)   ③ 时间窗 =「去年」
  ④ 用户数翻倍           ⑤ 增长由它导致(归因)
  ⑥ 两个数字口径一致、可作同一基准(隐含前提)

汇报:
  声明 1  "营收增长"        ✓ 已验证(A 级:10-K, p.42)
  声明 2  "增长 20%"        ? 未决(来源矛盾:18% vs 20%)
  声明 3  "时间窗是去年"    ✓ 已验证(A 级)
  声明 4  "用户数翻倍"      ○ 未覆盖(本轮范围外)
  声明 5  "因为用户数…"     ? 未决(相关被说成因果)
  声明 6  "口径可比"        ? 未决(分母无数据)
  —— 6 条:2 已验证、3 未决、1 未覆盖
```

## 开新会话跑,别在老对话里跑

这套协议全部价值挂在一个区分上:「我打开了那个出处」和「我记得我打开过」。在一个长对话里,这个区分没有物理基础 —— agent 自己早先的结论,和它刚刚真读到的文件原文,在同一个窗口里是同一种 token。第 20 轮挣来的一个 `✓`,到第 400 轮会被当成依据花掉,而那时上下文里没有任何东西标注它是二手的。

`SKILL.md` §二 已经规定:自己上一轮的判断只是待核查的声明,不是终点。但在产出这条结论的那个会话里跑核查,等于让这条规则去对抗它自己的上下文。它会输。

所以:

- **开新会话。** 只喂要核查的那段话 / 那份文档 / 那条结论。
- **不要喂产出这条结论的历史。** 别给「我们目前查到这样」、别给上一份报告、别给已经带着勾的声明清单。那些材料是核查的*对象*,不是核查的背景。
- **一个会话一套声明。** 三份结论要审,就开三次。
- **更好:同一套声明开两三个独立会话各跑一遍。** 各趟抓到的错不一样,而且漏的不是同一类 —— 重新算出那个数字的一趟,和追问「这个数字是什么的计数」的一趟,干的是两种活。别用多数表决裁决分歧:一个错在两趟里存活、一趟里被抓到,它仍然是错。要取的是**并集**。
- 用 `fact-check-by-docs` 续接一份已有文档是这件事设计出来就为了支持的例外:状态由文档带着,新会话不需要任何别的东西。

## 设计取舍

这些是故意做的取舍,否则看起来像遗漏:

- **穷尽性无法自证。** 要证明没漏声明,得再做一次同样完整的拆解 —— 而那次一样无法自证。所以协议不依赖「漏一条就整体作废」(那是一个违规者自己观察不到的失败条件),它强制的是*可见分母*。
- **分级只做注解,状态才下结论。** 如果分级能顶替状态,「B 级」就会变成通往「已验证」的新洗白路径。所以非一手终点必须写成 `✓ 已验证(依据 B)`,不许光秃秃一个 ✓。
- **循环依据是「未决」的理由,不是第五种终点** —— 终点必须能终止。(A 引 B、B 引 A 是终止失败。)
- **条件真是注解**(`✓ 在该前提下成立`),不是独立的认知状态;否则状态字段会把结果和过程混在一起。
- **预测、应然、价值只列出不追链。** 它们不是未决 —— 它们本来就没有真假。标成「未决」是范畴错误。
